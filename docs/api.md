# API Orbit

Orbit публикует расписание как открытый статичный API: готовые JSON-файлы на GitHub Pages. Без ключей и регистрации, только чтение. Расписание — ровно то, что опубликовало учебное заведение; Orbit не связан ни с одним из них.

- **Адрес:** `https://nikkishura.github.io/orbit-schedule/api/v1/`
- **Описание в OpenAPI 3.1:** [`openapi.json`](https://nikkishura.github.io/orbit-schedule/api/v1/openapi.json). Его можно открыть в [Swagger Editor](https://editor.swagger.io) (File → Import URL), Redoc, Scalar, Postman или сгенерировать по нему клиент.
- **Схемы файлов:** [`schemas/`](../api/v1/schemas/) для служебных файлов и [схема стандарта](../standard/schema/schedule.schema.json) для недель.

## Файлы

| Адрес | Что это |
|---|---|
| `index.json` | входная точка: список источников и пути к их файлам |
| `<источник>/status.json` | когда источник проверяли в последний раз и что вышло с каждой неделей |
| `<источник>/catalog.json` | опубликованные недели и все группы, преподаватели, корпуса из них |
| `<источник>/<понедельник>.json` | неделя учебного заведения целиком (около 1,7 МБ, по сети около 130 КБ) |
| `<источник>/groups/<id>/<понедельник>.json` | неделя одной группы (около 15 КБ) |
| `<источник>/teachers/<id>/<понедельник>.json` | неделя одного преподавателя |

Недели — документы [стандарта Orbit](../standard/). Данные обновляются днём каждые 10 минут, ночью раз в час.

## Как пользоваться

1. Возьмите `index.json` и выберите источник. Пути в нём — относительно `index.json`.
2. Возьмите `catalog.json` источника: в нём недели (`weeks`) и id групп и преподавателей.
3. Возьмите неделю группы: `<источник>/groups/<id>/<понедельник>.json`.

```bash
curl -s https://nikkishura.github.io/orbit-schedule/api/v1/index.json
curl -s https://nikkishura.github.io/orbit-schedule/api/v1/spk/catalog.json
```

В браузере (CORS открыт для всех сайтов):

```js
const base = "https://nikkishura.github.io/orbit-schedule/api/v1/";
const index = await (await fetch(base + "index.json")).json();
const spk = index.sources.find((s) => s.id === "spk");
const catalog = await (await fetch(base + spk.catalog)).json();
```

Адреса стройте по `index.json` и `catalog.json`, а не угадывайте: недели, которых нет в `catalog.json`, могут быть не опубликованы.

## Что важно знать о данных

- **Охват.** У каждой недели есть `publication.coverage` — что она охватывает: всё учебное заведение или часть корпусов. Вне охвата расписание неизвестно, а не пусто. Файл группы внутри охвата без пар — это «пар нет».
- **Свежесть.** `status.json` → `checkedAt` — когда источник проверили последний раз. Если это было давно, источник, скорее всего, недоступен, и опубликованное могло устареть. Когда расписание изменилось в последний раз, показывает `provenance.retrievedAt` документа недели.
- **`404`** значит «такого файла нет»: неизвестный источник, id или неделя, которую не публиковали. Это не «пар нет».
- **Одинаковые ФИО.** Разные записи с одним ФИО — разные id. Orbit их не склеивает: это могут быть однофамильцы.

## Кэш

Ответы кэшируются до 10 минут (`Cache-Control: max-age=600`). Чтобы проверить файл, не скачивая его заново, передайте `ETag` из прошлого ответа в `If-None-Match`: если файл не менялся, вернётся `304 Not Modified` без тела. Браузер делает это сам.

Пожалуйста, не опрашивайте API чаще раза в 10 минут: чаще данные не обновляются.

## Совместимость

Версия — часть адреса (`/api/v1/`, [ADR 0008](decisions/0008-versioned-data-api.md)).

- Внутри `v1` появляются только новые необязательные поля, файлы и источники. **Пропускайте незнакомые поля** — тогда ваш код не сломается.
- Удаление, переименование или смена смысла поля, смена адресов, новое значение в перечне (например, `result` в `status.json`) — это `v2`. Она выйдет рядом с `v1`, а `v1` будет обновляться ещё не меньше трёх месяцев. О сроке отключения будет написано в [журнале изменений](../CHANGELOG.md).

Описание API проверяется тестами: спецификация — по официальной схеме OpenAPI 3.1, файлы — по своим схемам перед каждой публикацией ([ADR 0009](decisions/0009-api-description.md)).
