# 0002. Модель документа публикации

**Статус:** принято 2026-11-08.

## Контекст

[ADR 0001](0001-schema-format.md) выбрал JSON и JSON Schema. Теперь нужно решить, как устроен один документ стандарта, и ответить на открытые вопросы из [требований](../standard/requirements.md#открытые-вопросы).

## Решение

1. **Единица — публикация за диапазон дат.** Один документ описывает расписание учебного заведения за период `period.start`–`period.end` (включительно). Неделя — частный случай. Так же записывается и семестровая таблица из xlsx.
2. **Охват публикации указывается явно** (`coverage`): всё заведение, список корпусов или список групп. День без пар внутри охвата означает «пар нет», всё вне охвата — «неизвестно».
3. **Корпус называется `building`** («корпус»): одно здание или площадка с одним адресом. Если понадобятся филиалы или кампусы из нескольких корпусов, их можно добавить позже необязательной сущностью `campus` — это совместимое изменение.
4. **Справочники и пары раздельно.** В документе есть списки `buildings`, `rooms`, `groups`, `teachers`, `subjects`, а пары (`lessons`) ссылаются на них по `id`.
5. **`id` — идентификатор источника** (например, GUID из 1С), строка без формата. Он уникален внутри своего списка. Собственных идентификаторов Orbit стандарт не вводит.
6. **Три состояния значения.** Поля нет — источник ничего не сообщил. Явная заглушка («ВАКАНСИЯ») — отдельный вид значения с исходным текстом. Обычное значение — ссылка на справочник. Пустые списки запрещены, чтобы «пусто» не путалось с «не сообщено».
7. **Время — у пары.** У пары есть номер (`period`) и/или время (`start`, `end`, местное `ЧЧ:ММ`). Даты — календарные (`ГГГГ-ММ-ДД`). Часовой пояс указывается один раз у учебного заведения (имя из базы IANA).
8. **Сетка звонков — необязательный справочник** (`bellSchedules`). Она не подменяет время пары: если у пары нет времени, оно не берётся из сетки.
9. **Происхождение обязательно** (`provenance`): коннектор, источник, момент получения данных и, если есть, ревизия источника.
10. **Расширения — только в полях `x-…`.** Любой объект может содержать поля с префиксом `x-`; другие неизвестные поля запрещены.
11. **Ключи — на английском, в `camelCase`.** Описания полей в схеме — на русском, как и остальная документация.

## Последствия

- Приложение может отличить «пар нет» от «не опубликовано» без эвристик.
- Коннектор обязан явно указать охват. Если источник отдаёт только один корпус, коннектор пишет именно его, а не «всё заведение».
- Часть правил JSON Schema не выражает: уникальность `id`, существование ссылок. Их проверяет валидатор в `standard/tools/`.
