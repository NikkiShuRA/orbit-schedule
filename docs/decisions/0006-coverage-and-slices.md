# 0006. Составной охват, охват по преподавателям и нарезка данных для приложения

**Статус:** принято 2026-11-08. Дополнено [ADR 0008](0008-versioned-data-api.md): раскладка лежит под `api/v1/`, служебные файлы меняются только совместимо.

## Контекст

Приложению нужны маленькие файлы: неделя одной группы или одного преподавателя, а не неделя всего заведения на 1,7 МБ ([#9](https://github.com/NikkiShuRA/orbit-schedule/issues/9), [ADR 0005](0005-offline-storage.md)).

Хочется, чтобы такой файл оставался обычным документом стандарта: тогда его может прочитать любая программа, а не только наше приложение. В стандарте 0.1 этому мешают две вещи:

1. Охват (`coverage`) бывает ровно одним из трёх: всё заведение, список корпусов или список групп. Охвата «по преподавателю» нет.
2. Охваты нельзя сочетать. А это нужно для честности. СИЭУиП выкладывает неделю по корпусам: сейчас опубликованы 4 корпуса из 7. Про пары преподавателя или группы в остальных трёх корпусах ничего не известно. Честно сказать можно только «все пары этого преподавателя **в корпусах 1–4**».

## Решение

### Стандарт 0.2

1. **Поля охвата можно сочетать, и они сужают друг друга.** `{"buildingIds": ["b-1"], "teacherIds": ["t-1"]}` означает: «все пары преподавателя `t-1` в корпусе `b-1`». Поле, которого нет, ничего не ограничивает. Внутри охвата день без пар по-прежнему означает «пар нет», вне охвата — «неизвестно».
2. **Новое поле охвата `teacherIds`.**
3. **`{"institution": true}` остаётся отдельным вариантом** и не сочетается с другими полями: в сочетании оно ничего бы не добавило. Пустой охват `{}` запрещён.
4. **Совместимость.** Каждый документ 0.1 остаётся правильным документом 0.2, а его охват значит то же самое. Поэтому версия меняется на 0.2.0, и валидатор принимает `standardVersion` 0.1.x и 0.2.x.
5. **Новая проверка-предупреждение:** пара, которая явно не попадает в охват (корпус пары не в `buildingIds`, ни одна из её групп не в `groupIds`, ни один преподаватель не в `teacherIds`). Это предупреждение, а не ошибка: так данные остаются такими, как их опубликовали.

### Нарезка (`orbit slice`)

6. **Из каждой недели нарезаются файлы на группу и на преподавателя.** Каждый — документ стандарта:
   - охват — охват исходной недели плюс `groupIds` или `teacherIds` этой группы или преподавателя;
   - пары — все пары исходной недели, где есть эта группа или этот преподаватель;
   - в справочниках — только то, на что ссылаются эти пары, и сама группа или преподаватель;
   - `provenance` — тот же, что у исходной недели: нарезка ничего не добавляет к данным.

   Файл создаётся для каждой группы и каждого преподавателя из оглавления, и тогда, когда пар нет: внутри охвата это правда («в опубликованных корпусах пар нет»). Если группы в самой неделе нет, её справочная запись берётся из оглавления, то есть из ближайшей недели, где она была. Чтобы отличить «пар нет» от «корпус группы ещё не опубликован», приложение сравнивает корпус группы (`buildingId`) с охватом недели.

   Нарезаются недели, которые закончились не раньше чем 8 дней назад: прошлая, текущая и следующие. Старые недели остаются на сайте целиком.
7. **Оглавление `catalog.json`** у каждого источника: группы и преподаватели (id, название, ФИО) из всех опубликованных недель и список недель с их охватом. По нему приложение строит поиск при выборе группы. Общий `data/index.json` перечисляет источники.
8. **Нарезка — производные данные.** Она выполняется при сборке сайта и в ветку `data` не коммитится. История нужна только у исходных недель, а нарезку из них всегда можно повторить.

Раскладка на сайте:

```
data/index.json                                   источники
data/<источник>/catalog.json                      группы, преподаватели, недели
data/<источник>/<понедельник>.json                неделя целиком (как сейчас)
data/<источник>/groups/<id>/<понедельник>.json    неделя группы
data/<источник>/teachers/<id>/<понедельник>.json  неделя преподавателя
data/<источник>/status.json                       когда проверяли
```

`catalog.json` и `index.json` — служебные файлы публикации, как и `status.json`. Это не часть стандарта, их формат может меняться вместе с приложением.

## Последствия

- Приложение скачивает десятки килобайт вместо мегабайтов и может честно сказать, какие корпуса ещё не опубликованы.
- Стандарт описывает и выборки из расписания, а не только публикации учебного заведения. Тот же механизм подойдёт для аудиторий (`roomIds`), когда понадобятся свободные кабинеты.
- Id группы и преподавателя попадает в адрес файла. У СИЭУиП это GUID из 1С. Проверка двух недель показала, что они стабильны: одна и та же группа или преподаватель везде имеет один id.
- Файлов становится много (сотни на неделю). Для Pages это не проблема, но сборка сайта займёт немного дольше.
