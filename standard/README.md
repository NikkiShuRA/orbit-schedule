# Стандарт данных расписания Orbit

**Версия 0.1** — черновая. До версии 1.0 возможны несовместимые изменения.

Открытый формат расписания учебного заведения. Им может пользоваться кто угодно, не только Orbit.

- Схема: [`schema/schedule.schema.json`](schema/schedule.schema.json) (JSON Schema 2020-12)
- Примеры: [`examples/valid/`](examples/valid/) — корректные, [`examples/invalid/`](examples/invalid/) — заведомо ошибочные, у каждого в поле `x-invalidBecause` написано, почему
- Почему так устроено: [требования](../docs/standard/requirements.md), [ADR 0001](../docs/decisions/0001-schema-format.md), [ADR 0002](../docs/decisions/0002-publication-document-model.md)

## Документ коротко

Один документ — публикация расписания одного учебного заведения за диапазон дат.

```jsonc
{
  "standardVersion": "0.1.0",
  "institution": { "id": "…", "name": "…", "timeZone": "Asia/Yekaterinburg" },
  "publication": {
    "period": { "start": "2026-11-02", "end": "2026-11-08" },
    "coverage": { "buildingIds": ["b-1"] }      // или { "groupIds": [...] }, или { "institution": true }
  },
  "provenance": { "connector": {…}, "source": {…}, "retrievedAt": "2026-11-08T09:30:00+05:00" },
  "buildings": [...], "rooms": [...], "groups": [...], "teachers": [...], "subjects": [...],
  "bellSchedules": [...],                        // необязательно
  "lessons": [
    {
      "date": "2026-11-02", "period": 7, "start": "18:00", "end": "19:20",
      "groups": [{ "groupId": "g-b" }],
      "subjectId": "s-math",
      "teachers": [{ "teacherId": "t-1" }],      // или { "placeholder": "unassigned", "sourceText": "ВАКАНСИЯ" }
      "rooms": [{ "roomId": "r-101" }],
      "note": "Перенос с 05.11"
    }
  ]
}
```

## Главные правила

- **Нет поля — источник ничего не сообщил.** Пустые списки запрещены. Явная заглушка источника записывается как `placeholder` с исходным текстом.
- **Внутри `coverage` день без пар — «пар нет», вне — «неизвестно».**
- **Время — у пары, как в источнике.** Пары с одним номером могут идти в разное время и пересекаться. Сетка звонков (`bellSchedules`) — только справка.
- **Даты календарные (`2026-11-02`), время местное (`18:00`),** часовой пояс один — у `institution`.
- **`id` — идентификатор источника,** уникален внутри своего списка. Связи только по `id`.
- **Свои поля — только с префиксом `x-`.** Остальные неизвестные поля запрещены.

## Проверка документа

Нужен Node.js 22 или новее.

```bash
cd standard
npm ci
npm run validate -- path/to/schedule.json
```

Валидатор сначала проверяет схему, затем то, что схема выразить не может: уникальность `id`, существование ссылок, порядок дат периода. Странности, которые бывают в настоящих данных (пара вне периода публикации, конец пары не позже начала), выводятся как предупреждения и не считаются ошибкой.

## Как менять стандарт

1. Найти реальный пример из источника, который стандарт не может выразить.
2. Добавить требование в [requirements.md](../docs/standard/requirements.md).
3. Изменить схему, добавить корректный и некорректный примеры, `npm test` должен проходить.
4. Новое необязательное поле — минорная версия, несовместимое изменение — мажорная (до 1.0 — минорная с пометкой в описании PR).
