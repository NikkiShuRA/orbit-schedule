# 0009. Описание API: OpenAPI 3.1, схемы служебных файлов и их проверка

**Статус:** принято 2026-11-08. Дополняет [ADR 0008](0008-versioned-data-api.md).

## Контекст

По [ADR 0008](0008-versioned-data-api.md) опубликованные данные — статичный API `api/v1` с договором: внутри версии только совместимые изменения. Но договор нигде не записан.

- Документы недель описывает схема стандарта, а формат служебных файлов `index.json`, `catalog.json` и `status.json` есть только в коде Go. Если поле в коде переименуют, `v1` сломается, и этого никто не заметит.
- Чтобы взять данные, человеку надо читать исходники или угадывать по примерам.
- В публикацию попадает `README.md` ветки `data`: он описывает ветку («руками её не правят»), а не API.

Варианты описания:

| | Что даёт | Чего не даёт |
|---|---|---|
| **OpenAPI 3.1** | общепринятый формат: его понимают Swagger UI, Redoc, Scalar, Postman, генераторы клиентов; схемы в нём — JSON Schema 2020-12, как у стандарта, поэтому неделю можно описать ссылкой на схему стандарта | для статичных файлов часть возможностей (запросы с телом, авторизация) не нужна |
| Только JSON Schema файлов | проще | не описывает адреса, параметры, ответы `304` и `404` |
| Только текст | проще всего | не проверяется машиной, расходится с кодом |

Варианты проверки самой спецификации:

| | Плюсы | Минусы |
|---|---|---|
| **Тест на Go по официальной схеме OpenAPI 3.1** (публикует OpenAPI Initiative) | без новых зависимостей: библиотека JSON Schema уже есть; проверяет структуру документа по первоисточнику | не проверяет стиль, только правильность |
| Линтер (Redocly CLI, Spectral) | больше правил, включая стиль | новая npm-зависимость и её обновления ради одного файла |

## Решение

1. **Описание — OpenAPI 3.1** в `api/v1/openapi.json`. В нём каждый адрес из раскладки ADR 0008, параметры с шаблонами (`source`, `week`, id), ответы `200`, `304` и `404`, примеры. `jsonSchemaDialect` — JSON Schema 2020-12, как у стандарта.
2. **Служебные файлы получают JSON Schema** в `api/v1/schemas/`: `index.schema.json`, `catalog.schema.json`, `status.schema.json`. Общие части (учебное заведение, корпус, группа, охват) — ссылками на схему стандарта, а не копией.
3. **Схемы открыты для добавлений.** Они не запрещают незнакомые поля (`additionalProperties` не закрыт): по ADR 0008 новое необязательное поле — совместимое изменение, и старый читатель, который проверяет ответ старой схемой, не должен на нём падать. Значения с перечнем (`result` в `status.json`) закрыты: новое значение — это `v2`.
4. **Описание публикуется вместе с данными:** `api/v1/openapi.json` и `api/v1/schemas/…`. `$id` схем — их адрес на сайте. Его можно открыть в любом инструменте OpenAPI. `README.md` ветки `data` в API больше не попадает.
5. **Проверка — тесты на Go, без новых зависимостей:**
   - `openapi.json` проходит официальную схему OpenAPI 3.1 (копия в `api/v1/testdata/`, лицензия Apache-2.0, совместима с AGPL-3.0);
   - все схемы компилируются, все ссылки в спецификации находятся, все примеры проходят свои схемы;
   - поля в структурах Go и в схемах совпадают в обе стороны: поле, добавленное в код без описания, роняет тест;
   - вывод `orbit fetch` и `orbit slice` в тестах CLI проходит схемы.
6. **`orbit` проверяет служебные файлы перед записью,** как уже проверяет документы недель: файл, который нарушает договор, не публикуется, а прошлая правильная версия остаётся на месте.
7. **Инструкция для людей** — `docs/api.md`: адрес, примеры запросов, правила совместимости, кэш и CORS.
8. **Swagger UI на нашем сайте пока не размещаем.** Это чужой JavaScript на нашем домене, а кнопка «попробовать запрос» для статичных GET-файлов почти ничего не даёт. Спецификацию по адресу можно открыть в editor.swagger.io и других инструментах. Страница с документацией может появиться вместе с приложением, когда будет решено, как оно собирается.

## Последствия

- Любое изменение формата служебных файлов — это правка схемы в том же PR, иначе падают тесты. Несовместимое изменение видно на ревью по диффу схемы.
- Новый источник не требует правки спецификации: `source` — параметр, список источников — в `index.json`. Имена `schemas`, `openapi` и `index` заняты описанием API и источником быть не могут.
- Официальную схему OpenAPI обновляем вручную, когда OpenAPI Initiative выпускает новую редакцию для 3.1; Dependabot её не видит.
- Схема недели — схема стандарта по её `$id` (`raw.githubusercontent.com`). Отдельная копия в API не публикуется, чтобы у одного `$id` не было двух адресов.
