# 0008. Опубликованные данные — статичный API с версией в адресе

**Статус:** принято 2026-11-08. Дополнено [ADR 0009](0009-api-description.md): описание API в OpenAPI 3.1 и схемы служебных файлов. Дополняет [ADR 0004](0004-scheduled-publishing.md) (адрес данных) и [ADR 0006](0006-coverage-and-slices.md) (формат служебных файлов).

## Контекст

Публикация ([ADR 0004](0004-scheduled-publishing.md), [ADR 0006](0006-coverage-and-slices.md)) выкладывает на GitHub Pages набор JSON-файлов по адресу `https://nikkishura.github.io/orbit-schedule/data/`: недели целиком, недели групп и преподавателей, `catalog.json`, `index.json` и `status.json`. По сути это открытый API, только статичный. На раскладку файлов и формат служебных файлов будут опираться приложение и все, кто захочет взять данные.

У этого API нет версии.

- У документов стандарта версия есть (`standardVersion`), а у раскладки файлов и служебных файлов — нет. ADR 0006 прямо говорит, что их формат «может меняться вместе с приложением», и ADR 0007 (пункт 9) уже планирует такое изменение в `catalog.json`.
- Приложение работает без сети ([ADR 0005](0005-offline-storage.md)): его старая версия живёт в кэше у человека неделями и ходит по старым адресам. Несовместимое изменение по тому же адресу молча её сломает.
- Сейчас у данных нет потребителей: приложения ещё нет. Сменить адрес можно бесплатно. Позже это был бы переезд с поддержкой двух адресов.

Что Pages уже даёт API (проверено 2026-11-08): `Access-Control-Allow-Origin: *` — файлы можно читать с любого сайта; `ETag` и `Last-Modified` — повторная проверка неизменившегося файла отвечает `304`; `Cache-Control: max-age=600` — браузер и CDN держат копию до 10 минут, столько же, сколько между запусками публикации днём.

Варианты указания версии:

| | Плюсы | Минусы |
|---|---|---|
| **В адресе** (`/api/v1/`) | видно сразу; старая и новая версии лежат рядом; работает на любом статичном хостинге | при новой версии файлы публикуются дважды |
| В заголовке запроса (`Accept: …;version=2`) | адрес не меняется | статичный хостинг не умеет выбирать ответ по заголовку |
| Поле версии внутри файлов | ничего не надо переносить | старое приложение узнаёт о несовместимости, только когда уже скачало файл, и ему некуда идти за старым форматом |

## Решение

1. **Адрес:** `https://nikkishura.github.io/orbit-schedule/api/v1/`. Слово `api` показывает, что это интерфейс для программ, а не страница для людей; `v1` — версия договора. Внутри — та же раскладка, что в ADR 0006:

   ```
   api/v1/index.json                            источники
   api/v1/<источник>/status.json                когда источник проверяли
   api/v1/<источник>/catalog.json               группы, преподаватели, недели
   api/v1/<источник>/<понедельник>.json         неделя целиком
   api/v1/<источник>/groups/<id>/<понедельник>.json
   api/v1/<источник>/teachers/<id>/<понедельник>.json
   ```

   Входная точка — `index.json`; остальные адреса приложение строит по нему и по `catalog.json`, а не по догадке. Старый адрес `/data/` больше не публикуется: перенаправлений Pages не умеет, а держать две копии ради несуществующих потребителей незачем.

2. **Версия — договор о совместимости.** В пределах `v1` разрешено только то, что не ломает старого читателя:
   - добавить новое необязательное поле, файл или источник;
   - добавить значение там, где читатель обязан пропускать незнакомое.

   Читатель обязан игнорировать незнакомые поля. Всё остальное — несовместимо и требует `v2`: удалить или переименовать поле или файл, поменять тип или смысл поля, поменять раскладку адресов, сделать обязательным то, что было необязательным.

3. **Документы стандарта внутри API** несут свою версию (`standardVersion`). Если новая версия стандарта несовместима со старой, публикация документов в ней — тоже повод для `v2`: старое приложение должно продолжать получать документы, которые умеет читать.

4. **Переход на новую версию.** `v2` публикуется рядом с `v1`, а не вместо неё. `v1` продолжает обновляться не меньше трёх месяцев после выхода версии приложения, которая умеет `v2`: за это время установленные приложения успевают обновиться. Срок отключения пишется в CHANGELOG заранее.

5. **Путь задан в одном месте** — переменной в `.github/workflows/publish.yml`. `orbit slice` о версии не знает: он пишет в каталог, который ему дали.

## Последствия

- Адрес данных в README, AGENTS.md и ADR 0004 меняется на `/api/v1/`; старые ссылки на `/data/` перестают работать.
- Адрес данных в приложении — настройка ([ADR 0003](0003-stack-and-hosting.md), [ADR 0005](0005-offline-storage.md)), а версия — часть этого адреса. Приложение знает, какую версию оно умеет читать.
- Изменение `catalog.json` из ADR 0007 (пункт 9) — добавление полей, то есть совместимое: оно попадёт в `v1`.
- Несовместимое изменение стоит дороже: две раскладки в публикации на время перехода. Это плата за то, что офлайн-приложение не ломается молча.
