# 0007. Полные недели в офлайне и несколько расписаний сразу

**Статус:** принято 2026-11-08. Дополняет [ADR 0005](0005-offline-storage.md).

## Контекст

По [ADR 0005](0005-offline-storage.md) приложение хранит в кэше только файлы выбранной группы или преподавателя ([ADR 0006](0006-coverage-and-slices.md)). Этого мало для двух вещей.

**Без сети нужно больше, чем своя группа.** Свободные кабинеты — одна из главных функций Orbit. Их можно посчитать только по расписанию всего учебного заведения: по файлу одной группы не видно, кто занимает кабинет. Без сети также полезно посмотреть чужую группу («у друга сейчас пара?») или преподавателя («где сейчас куратор?»).

Сколько стоит полная неделя (замерено 2026-11-08):

| | СПК | СИЭУиП |
|---|---|---|
| Файл недели | 1,8 МБ | 1,7 МБ |
| По сети (Pages отдаёт сжатым) | около 130 КБ | около 130 КБ |
| Файл одной группы | около 18 КБ | около 15 КБ |

Если файл не менялся, Pages отвечает `304 Not Modified`, и повторная проверка почти ничего не стоит.

**Один человек бывает под несколькими id.**
- Преподаватель-совместитель работает в двух учебных заведениях. У каждого своя 1С и свои id. На неделе 2026-11-09 у СИЭУиП и СПК нет ни одного общего ФИО, но с новыми источниками такое появится.
- Внутри одного заведения в справочнике СПК у 43 ФИО по несколько id. Часть из них — однофамильцы. Но 1С часто заводит для сотрудника, работающего ещё и по совместительству, вторую запись, и тогда пары одного человека делятся между двумя id.
- Студенту тоже бывает нужно несколько расписаний: учится в двух местах, нужны две подгруппы или своя группа плюс группа друга.

Склеить записи по ФИО — это догадка. Однофамильцы реальны, а источник не говорит, что две записи — один человек.

## Решение

### Полные недели в офлайне

1. **Сначала своё, потом остальное.** При открытии приложение по-прежнему сначала загружает файлы выбранных групп и преподавателей, как в ADR 0005: первый экран появляется быстро.
2. **Затем в фоне подкачиваются текущая и следующая недели целиком** у тех учебных заведений, к которым относятся выбранные расписания. Они кладутся в тот же Cache API. Порядок обновления тот же: сначала сеть, при сбое — сохранённая копия.
3. **Бережём трафик.** Если включён режим экономии (`Save-Data`) или сеть медленная, фоновая загрузка не выполняется. Свободные кабинеты и чужие расписания тогда загружаются, когда человек их открывает.
4. **Что работает на полных неделях:** свободные кабинеты, просмотр чужих групп и преподавателей, переключение на другую группу без сети. Возраст данных показывается так же честно, как и для своей группы.
5. Прошедшие недели удаляются из кэша, как и раньше.

Этим уточняется пункт 4 ADR 0005: свободные кабинеты считаются прямо по полным неделям из кэша. Понадобится ли для этого IndexedDB, решим, когда дойдём до этой функции. Полная неделя — это несколько тысяч пар, их можно перебрать и в памяти.

### Несколько расписаний

6. **Коннекторы и стандарт записи не склеивают.** Каждый преподаватель и каждая группа остаются такими, как их опубликовал источник: со своим id в своём учебном заведении.
7. **«Моё расписание» — это набор записей**, который человек выбирает сам: одна или несколько групп или преподавателей, в том числе из разных учебных заведений. Приложение показывает их одним днём, и у каждой пары видно, откуда она. Если пары накладываются по времени, это видно, а приложение их не «чинит».
8. **Подсказка, а не автоматика.** Если в другом учебном заведении или под другим id есть запись с таким же ФИО, приложение может спросить: «Это тоже вы?». Решает человек. Выбор хранится только на устройстве (в настройках, ADR 0005, пункт 3) и никуда не отправляется.
9. **Поиск должен различать одинаковые ФИО.** Сейчас в `catalog.json` у преподавателя есть только id и ФИО, поэтому две записи с одинаковым ФИО в поиске неотличимы. Вместе с приложением в оглавление добавим то, чем записи различаются, например отделение или группы, у которых преподаватель ведёт пары. Оглавление — служебный файл публикации (ADR 0006), стандарт это не затрагивает.

## Последствия

- Публикацию менять не нужно: полные недели уже лежат на сайте рядом с нарезкой.
- Приложение со свободными кабинетами тратит больше трафика и места: две полные недели одного заведения — около 260 КБ по сети и несколько мегабайт в кэше.
- Настройки хранят не одну группу, а список выбранных записей. Это нужно учесть с самого начала, иначе потом придётся переделывать формат настроек.
- Если человек объединил чужие записи по ошибке, он увидит лишние пары. Это его выбор, и его легко отменить, а данные от этого не портятся.
