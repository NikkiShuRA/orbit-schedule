# 0010. Приложение: React, Vite, PWA на Workbox и инструменты разработки

**Статус:** принято 2026-11-08. Уточняет [ADR 0003](0003-stack-and-hosting.md) (приложение на TypeScript) и [ADR 0005](0005-offline-storage.md) (чем делать service worker).

## Контекст

Перед первой версией приложения ([#11](https://github.com/NikkiShuRA/orbit-schedule/issues/11)) нужно выбрать фреймворк, сборку и инструменты. Что требуется:

- TypeScript ([ADR 0003](0003-stack-and-hosting.md)), статичные файлы на GitHub Pages, без своего сервера;
- быстро открываться на слабом Android по мобильной сети: Orbit открывают на бегу перед парой;
- PWA и работа без сети по [ADR 0005](0005-offline-storage.md): сначала сеть, но не дольше 3 секунд, затем копия из кэша;
- поиск по сотням групп и преподавателей, несколько расписаний сразу, потом свободные кабинеты ([ADR 0007](0007-full-weeks-and-several-schedules.md));
- проект ведёт один человек с помощью ИИ-агентов: важны распространённость, предсказуемость и долгая поддержка инструментов.

Сравнение фреймворков (версии и лицензии по npm на 2026-11-08; размер — сжатый код фреймворка в сборке):

| | Размер | Плюсы | Минусы |
|---|---|---|---|
| Без фреймворка | 0 | ничего лишнего | состояние интерфейса (поиск, несколько расписаний, сеть) обновляется вручную — источник ошибок |
| **React 19** (MIT) | около 55–60 КБ | самая большая экосистема и база знаний, лучше всего знаком ИИ-агентам, востребованный навык; React Compiler сам оптимизирует перерисовку | самый тяжёлый из рассмотренных; новые возможности рассчитаны на работу с сервером, которого у нас нет |
| Preact 11 (MIT) | около 8,5 КБ с signals | API React при весе в 6–7 раз меньше | новая мажорная версия (сентябрь 2026) |
| Svelte 5 (MIT) | 3–10 КБ | самый лёгкий код, подсказки о доступности в компиляторе | свой синтаксис и своя проверка типов |
| Solid, Lit, Vue | 6–47 КБ | | меньше экосистема (Solid), веб-компоненты (Lit), вес (Vue) |

Автор выбрал React ради экосистемы и навыка. Цену — вес — снижаем и держим под контролем (пункт 6).

## Решение

1. **React 19 + TypeScript.** Компоненты — функции с хуками. React Compiler (`babel-plugin-react-compiler`) включён: он сам расставляет мемоизацию, `useMemo` и `useCallback` вручную не пишем без измеренной причины. Server Components и фреймворки поверх React (Next.js и т. п.) не используем: сервера нет.
2. **Сборка — Vite** с `@vitejs/plugin-react`. Проверка типов — `tsc --noEmit` в строгом режиме (`strict`, `noUncheckedIndexedAccess`). Версию TypeScript берём последнюю, с которой работает весь набор инструментов; если TypeScript 7 с чем-то несовместим, временно остаёмся на 5.x.
3. **PWA — `vite-plugin-pwa` в режиме `injectManifest`** на модулях Workbox:
   - оболочка приложения кэшируется заранее (precache) и обновляется с версией приложения, старые версии удаляются;
   - данные — `NetworkFirst` с `networkTimeoutSeconds: 3`, ровно как в ADR 0005; удаление прошедших недель — своим кодом в service worker;
   - service worker пишем сами на TypeScript, а не генерируем: правила кэша данных — часть честности данных, их нужно видеть в коде.
4. **Без лишних библиотек на старте.** Каждую новую библиотеку — только с обоснованием в PR, по правилам AGENTS.md.
   - **Состояние** — средства React (`useState`, `useReducer`, контекст, `useSyncExternalStore` для сети и кэша), без Redux и подобных.
   - **Данные** — `fetch` и свои небольшие хуки: кэш и офлайн делает service worker, отдельная библиотека запросов не нужна.
   - **Навигация** — без роутера: состояние, которым делятся, — в параметрах адреса (`?s=spk&g=g-301`). Такие ссылки работают на GitHub Pages без перенаправлений и их можно отправить другу.
   - **Стили** — обычный CSS и CSS Modules (встроены в Vite), без CSS-фреймворков и CSS-in-JS: ничего не выполняется во время работы.
5. **Качество:**
   - **Biome** — линтер и форматирование одним инструментом (вместо ESLint и Prettier);
   - **Vitest** + **Testing Library** — тесты логики (неделя, текущая пара, возраст данных, разбор документов) и компонентов;
   - **Playwright** — проверка в настоящем браузере, в первую очередь работы без сети; подключаем, когда появится что проверять;
   - **доступность** — семантическая разметка, работа с клавиатуры и экранным диктором, достаточный контраст; правила a11y в Biome включены.
6. **Бюджет веса.** Код, который загружается при первом открытии, — не больше **100 КБ JavaScript в сжатом виде** (из них около 60 КБ — React). Проверяет `size-limit` в CI; превышение роняет проверку. Редкие экраны (свободные кабинеты, настройки) загружаются отдельно, когда их открывают (`React.lazy`).
7. **Каталог `app/`** со своим `package.json` (npm, `package-lock.json`, `npm ci`), как `standard/`. Node.js 22+.
8. **Адрес данных — настройка сборки** (`VITE_DATA_URL`), по умолчанию `./api/v1/` на том же сайте ([ADR 0003](0003-stack-and-hosting.md), [ADR 0008](0008-versioned-data-api.md)).
9. **Публикация:** `publish.yml` собирает приложение из того же коммита и кладёт его в корень сайта, данные — в `api/v1/`, как прежде ([ADR 0004](0004-scheduled-publishing.md)). Проверки приложения (типы, Biome, тесты, сборка, бюджет веса) — отдельный workflow на каждом PR.
10. **Язык интерфейса — русский.** Тексты — простым языком, без канцелярита. Переводы не закладываем, пока не понадобятся.

## Последствия

- Первое открытие тяжелее, чем со Svelte или Preact, примерно на 50 КБ сжатого JavaScript. После установки PWA код берётся из кэша, и разница почти пропадает. Бюджет веса не даёт ей расти незаметно.
- Если вес станет проблемой, переход на Preact через `preact/compat` возможен почти без переписывания: API совпадает.
- Зависимостей npm станет заметно больше, чем в `standard/`. Их обновления идут через Dependabot отдельной группой и проверяются человеком, как и остальные.
- Чтобы новые проверки приложения стали обязательными для слияния, их нужно добавить в правило защиты `main` («Protect main»). Это делает владелец репозитория.
