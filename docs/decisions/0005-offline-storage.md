# 0005. Офлайн в приложении: файлы данных в Cache API, настройки в localStorage

**Статус:** принято 2026-11-08.

## Контекст

Приложение ([#11](https://github.com/NikkiShuRA/orbit-schedule/issues/11)) должно показывать расписание без сети: в корпусе часто нет связи, а пара начинается сейчас. При этом действует принцип честности: если данные взяты из кэша, приложение говорит, что они могли устареть.

Что известно о данных ([ADR 0004](0004-scheduled-publishing.md)):

- это статичные JSON-файлы на GitHub Pages, свежесть которых показывает `status.json`;
- одна неделя СИЭУиП целиком весит около 1,7 МБ, а с другими учебными заведениями данных станет больше.

Варианты хранения в браузере:

| | Для чего годится | Ограничения |
|---|---|---|
| **Cache API + service worker** | хранить готовые HTTP-ответы — ровно наши файлы | только целые ответы, без запросов по содержимому |
| **localStorage** | маленькие настройки | синхронный (блокирует интерфейс), около 5 МБ, только строки |
| **IndexedDB** | структурированные данные и запросы по ним | сложнее; разобранные копии нужно поддерживать в актуальном состоянии |

Браузер может очистить хранилище сайта сам. Safari на iPhone удаляет всё, что сохранил сайт, после 7 дней без посещений, если сайт не установлен на главный экран; установленного PWA это не касается.

## Решение

1. **Файлы данных и `status.json` — в Cache API** через service worker.
   - Данные: сначала сеть, но не дольше 3 секунд; если сеть не ответила — сохранённая копия из кэша. Как это выглядит для человека:

     | Ситуация | Что видно |
     |---|---|
     | Нормальная сеть | свежее расписание и «проверено N минут назад» |
     | Сети нет совсем | сразу сохранённая копия с пометкой «нет сети, показана копия от …» — без сети запрос падает мгновенно, ждать нечего |
     | Сеть есть, но не работает (слабый сигнал, Wi-Fi без интернета) | не больше 3 секунд ожидания, затем сохранённая копия с той же пометкой |
     | Первый запуск без сети | «нет сохранённого расписания» — один раз приложение нужно открыть с интернетом |

     Почему не наоборот (сразу кэш, свежее — в фоне): у расписания важнее всего замены. Если сначала показать старую копию, а через секунду подменить её, человек успеет увидеть старую аудиторию и уйти не туда. При живой сети лучше подождать секунду и сразу показать правду.
   - Оболочка приложения (HTML, JS, CSS) — заранее в кэше, обновляется вместе с версией приложения; старые версии кэша удаляются при активации нового service worker.
   - В кэше лежит только нужное: выбранные группы или преподаватели за текущую и следующую недели. Прошедшие недели удаляются.

2. **Возраст данных виден всегда,** а не только без сети: «проверено 20 минут назад» по `status.json` (`checkedAt`). Без сети приложение явно пишет, что показывает сохранённую копию, и сколько ей лет. Время изменения расписания — `provenance.retrievedAt` документа.

3. **localStorage — только для маленьких настроек:** выбранная группа или преподаватель, тема. Никогда — для расписания. Доступ к нему всегда обёрнут в обработку ошибок: в приватном режиме он может быть недоступен.

4. **IndexedDB пока не используем.** Он понадобится, когда появятся запросы по всем данным сразу: поиск, свободные кабинеты по всему зданию, сравнение версий для показа замен. Тогда — отдельное решение.

5. **Защита от очистки:**
   - после выбора группы приложение просит постоянное хранилище (`navigator.storage.persist()`);
   - предлагает установить PWA на главный экран;
   - пустой кэш — нормальная ситуация: без сети приложение честно пишет «нет сохранённого расписания», а не показывает пустую неделю.

6. **Адрес данных — настройка,** как требует [ADR 0003](0003-stack-and-hosting.md).

Чем делать service worker — вручную или через Workbox — решается вместе с выбором инструментов приложения.

## Последствия

- Нужны маленькие файлы на группу и преподавателя ([#9](https://github.com/NikkiShuRA/orbit-schedule/issues/9)): тянуть 1,7 МБ ради одной группы по мобильной сети и хранить их в кэше — расточительно. #9 надо сделать до приложения.
- `status.json` становится частью договора между публикацией и приложением; его формат меняем согласованно.
- Офлайн не бесконечен: на iPhone без установки данные могут пропасть через неделю. Приложение должно это переживать, а не ломаться.
